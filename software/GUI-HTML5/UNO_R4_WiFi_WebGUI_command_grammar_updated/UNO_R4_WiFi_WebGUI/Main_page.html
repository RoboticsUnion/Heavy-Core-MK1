Heavy-Core-MK1

Heavy-Core-MK1 is the development of a modular robotic arm platform. The goal is to create a scalable, affordable robotics ecosystem where hardware and software are engineered together from the ground up. The first two axes have already been designed, printed, assembled, and successfully tested. In parallel, we are developing our own control software for precise motion control.

Our Vision

We aim to build a 6 DOF robotic arm that:

-> Is upgradeable with interchangeable end-effectors

-> Is structurally optimized for strength-to-weight efficiency

-> Includes a custom-developed control software

-> Allows future automation features

-> Serves as a platform for robotics development

Custom Control Software

Our robotic arm will not rely solely on position control. We are developing a control application that will include:

-> Real-Time position feedback

-> Inverse kinematics calculations

-> Intuitive controls

-> Integrated arm simulation to prevent collisions or overload situations

-> Expandable architecture for future features

Code Guidelines

The Robotics Union Control Software uses a command-based system to control the robotic arm and its peripheral hardware. Each command has a defined syntax and specific parameters. Commands must follow the specified format to be accepted by the control software.

1. Emergency & Program Control

XSTOPX - Emergency Stop

XSTOPX triggers the emergency shutdown function. In an emergency situation, it cuts the power supply to the system. This command is intended for emergency situations only. The emergency shutdown must be supported by an independent hardware safety system.

Syntax: XSTOPX [optional parameter]

Example: XSTOPX

Allowed parameters: #, 1, DUMMY or empty

XENDX - Program Shutdown

XENDX provides a controlled way to terminate the running program. Unlike XSTOPX, this command is intended for normal program termination and does not represent an emergency shutdown.

Syntax: XENDX [optional parameter]

Example: XENDX

Allowed parameters: #, 1, DUMMY or empty

2. Axis & Motor Control

ENAM - Enable Axis Motors

Enables the motors of the selected axes. The command accepts either ALL or individual axis numbers. Multiple axes can be selected in one command.

Syntax: ENAM ALL / ENAM 1,2,3

Examples:

ENAM ALL

ENAM 1,2,3

DISM - Disable Axis Motors

Disables the motors of the selected axes. Accepts ALL or individual axis numbers from 1 to 6.

Examples:

DISM ALL

DISM 2,4,6

ENAC - Enable Axis Cards

Enables the selected axis controller cards. The command accepts ALL or individual axis numbers from 1 to 6.

Examples:

ENAC ALL

ENAC 1,3,5

DISC - Disable Axis Cards

Disables the selected axis controller cards. Accepts ALL or individual axis numbers from 1 to 6.

Examples:

DISC ALL

DISC 1,2

3. Motion Control

MOVE - Cartesian Movement

MOVE commands the robotic arm to move to a specified target position. It uses six parameters representing the Cartesian position and orientation of the end effector.

Parameters:

X - Position along the X axis

Y - Position along the Y axis

Z - Position along the Z axis

Rx - Rotation around the X axis

Ry - Rotation around the Y axis

Rz - Rotation around the Z axis

Syntax: MOVE X Y Z Rx Ry Rz

Example:

MOVE 100 200 300 0 90 0

SINGLE JOINT - Individual Axis Movement

SINGLE JOINT allows direct movement of one individual joint. It is useful when a specific axis needs to be controlled without defining a complete Cartesian target position.

Full command: SINGLE JOINT MOVE axis value

Parameters:

Axis - Selected joint (1-7)

Value - Target movement value

Example:

SINGLE JOINT MOVE 1 90

REPEAT - Repeated Movement

REPEAT executes a movement sequence a specified number of times. It allows incremental changes to the X, Y and Z coordinates between repetitions. This function is intended for repetitive movement patterns and can serve as a foundation for more advanced movement paths, such as curve generation.

Parameters:

X - Initial X position

Y - Initial Y position

Z - Initial Z position

Rx - Initial X rotation

Ry - Initial Y rotation

Rz - Initial Z rotation

repeat_nbr - Number of repetitions

changex - X coordinate increment per repetition

changey - Y coordinate increment per repetition

changez - Z coordinate increment per repetition

Syntax:

REPEAT X Y Z Rx Ry Rz repeat_nbr changex changey changez

Example:

REPEAT 100 200 300 0 0 0 5 10 0 2

Example explanation:

The movement sequence is repeated 5 times. Each repetition changes the position by X +10, Y +0 and Z +2. The initial position is X=100, Y=200, Z=300.

4. System Configuration

SET - Motion Settings

SET is used to configure motion-related parameters. Values are specified inside square brackets.

Available settings:

SPEED[1-100] - Motion speed

ACCEL[1-100] - Acceleration

DECEL[1-100] - Deceleration

HOME[0-6] - HOME-related setting

Examples:

SET SPEED[50]

SET ACCEL[75]

SET DECEL[25]

HOME[3]

HOME - Homing Command

HOME is a separate command used to initiate a homing operation. It accepts the range 0 to 6, where 0 can represent a homing operation involving all axes, depending on the controller implementation.

Syntax: HOME[0-6]

Examples:

HOME[0]

HOME[1]

HOME[6]

5. Chamber Control

CHAMBER - Peripheral Control

CHAMBER controls the peripheral components of the robotic system, including the ventilation fan, lighting and power supply. It also provides access to sensor readings.

Fan control:

CHAMBER FAN ON - Enables the fan

CHAMBER FAN OFF - Disables the fan

CHAMBER FAN SPEED+ - Increases fan speed

CHAMBER FAN SPEED- - Decreases fan speed

CHAMBER FAN AUTO - Enables automatic fan control

Lighting:

CHAMBER LIGHTS ON - Turns the lights on

CHAMBER LIGHTS OFF - Turns the lights off

Power supply:

CHAMBER PSU ON - Enables the power supply

CHAMBER PSU OFF - Disables the power supply

Sensor readings:

CHAMBER READ - HUM - Reads humidity

CHAMBER READ - PRESS - Reads pressure

CHAMBER READ - TEMP - Reads temperature

CHAMBER READ - CONTROLER TEMP - Reads controller temperature

6. Command Syntax & Validation

All commands are validated using regular expressions. Invalid commands or incorrectly formatted parameters will not be accepted by the command parser.

General syntax rules:

-> Commands are case-sensitive unless explicitly handled otherwise.

-> Parameters must follow the defined command order.

-> Multiple axis selections can be separated by commas or spaces.

-> Numeric movement values may be positive or negative.

-> Decimal values are supported by MOVE commands.

-> Commands must match their defined syntax.
